\section{Le HTML, un langage de balisage}
% ============================================================

\textbf{HTML} signifie \textit{HyperText Markup Language} : langage de balisage hypertexte. Une page web est un simple fichier texte portant l'extension \texttt{.html}, que le navigateur lit et interprète pour construire l'affichage.

\begin{tcolorbox}[definition, title={Définition --- Langage de balisage}]
Un \textbf{langage de balisage} sert à \textit{décrire} un contenu, pas à effectuer des calculs. On entoure chaque morceau de texte d'une \textbf{balise} qui indique ce qu'il représente : un titre, un paragraphe, un lien, une image\dots

\vspace{3pt}
HTML n'est donc \textbf{pas un langage de programmation} : il n'a ni variables, ni conditions, ni boucles. Ces notions arriveront avec JavaScript, en semaine 6.
\end{tcolorbox}

\subsection{Anatomie d'une balise}

La plupart des éléments HTML fonctionnent par \textbf{paires} : une balise ouvrante et une balise fermante encadrent un contenu.

\vspace{6pt}
\begin{center}
\begin{tikzpicture}[font=\small]
  \node[font=\ttfamily\large] (code) {%
    \textcolor{accentBlue}{<p>}%
    \textcolor{cfptBlack}{~Bonjour tout le monde~}%
    \textcolor{accentBlue}{</p>}};

  \node[below=1cm of code, xshift=-3.0cm,
        text=accentBlue, font=\footnotesize\bfseries] (lo) {Balise ouvrante};
  \node[below=1cm of code, xshift=0cm,
        text=cfptDarkGrey, font=\footnotesize\bfseries] (ct) {Contenu};
  \node[below=1cm of code, xshift=3.0cm,
        text=accentBlue, font=\footnotesize\bfseries] (lf) {Balise fermante};

  \draw[-{Stealth[length=5pt]}, accentBlue!70, thick] (lo.north) -- ++(0,0.55);
  \draw[-{Stealth[length=5pt]}, cfptDarkGrey!70, thick] (ct.north) -- ++(0,0.55);
  \draw[-{Stealth[length=5pt]}, accentBlue!70, thick] (lf.north) -- ++(0,0.55);
\end{tikzpicture}
\end{center}
\vspace{2pt}

L'ensemble --- balise ouvrante, contenu, balise fermante --- forme un \textbf{élément}. La balise fermante se distingue par sa barre oblique : \texttt{</p>}.

\vspace{4pt}
Certains éléments n'encadrent aucun contenu et s'écrivent donc \textbf{seuls}. On les dit \textbf{auto-fermants} : \texttt{<img>} (une image), \texttt{<br>} (un retour à la ligne forcé), \texttt{<meta>}, \texttt{<link>}, \texttt{<input>}.

\subsection{Les attributs}

Une balise peut porter des \textbf{attributs}, qui précisent son comportement. Un attribut s'écrit dans la balise \textbf{ouvrante}, sous la forme \texttt{nom="valeur"}.

\begin{lstlisting}[language=HTML5, caption={Une balise, deux attributs}]
<a href="https://www.hepia.ch" target="_blank">Site de la hepia</a>
\end{lstlisting}

Ici, \texttt{href} indique la destination du lien et \texttt{target} précise qu'il doit s'ouvrir dans un nouvel onglet. Une balise fermante, elle, ne porte \textbf{jamais} d'attribut.

\subsection{L'imbrication : un document est un arbre}

Les éléments se placent les uns \textbf{dans} les autres. Cette imbrication n'est pas décorative : elle construit une structure arborescente que le navigateur, les moteurs de recherche et --- plus tard --- ton code JavaScript vont parcourir.

\vspace{8pt}
\begin{center}
\begin{tikzpicture}[font=\footnotesize,
  n/.style={draw=uniNavy, fill=uniNavy!8, rounded corners=2pt,
            inner sep=4pt, font=\ttfamily\footnotesize},
  f/.style={draw=uniGrey!55, fill=uniPaper, rounded corners=2pt,
            inner sep=4pt, font=\ttfamily\footnotesize},
  e/.style={uniGrey!70, thick}]

\node[n] (head) at (-3.0,-1.3) {<head>};
\node[n] (body) at (2.4,-1.3) {<body>};
\node[f] (title) at (-3.0,-2.6) {<title>};
\node[n] (h1)   at (0.4,-2.6) {<h1>};

\draw[e] (html) -- (head);

\draw[e] (head) -- (title);

\end{tikzpicture}
\end{center}
\vspace{2pt}

\begin{tcolorbox}[attention, title={La règle d'imbrication : premier ouvert, dernier fermé}]
Les balises se ferment dans l'ordre inverse de leur ouverture, comme des parenthèses. Elles ne peuvent pas se chevaucher.

\vspace{4pt}
\textcolor{successGreen}{\textbf{OUI}}\quad \texttt{<p>Un <strong>mot</strong> important</p>}\\[3pt]
\textcolor{alertRed}{\textbf{NON}}\quad \texttt{<p>Un <strong>mot</p></strong> important}

\vspace{4pt}
\textbf{Indente ton code} : un niveau d'indentation par niveau d'imbrication. C'est ce qui rend les erreurs visibles à l'\oe il nu.
\end{tcolorbox}

\subsection{Espaces, retours à la ligne et commentaires}

\begin{tcolorbox}[attention, title={Le HTML ignore ta mise en forme du texte}]
Dans un fichier HTML, plusieurs espaces consécutifs, les tabulations et les retours à la ligne sont \textbf{réduits à un seul espace} à l'affichage. Écrire trois lignes vides ne crée aucun blanc dans la page ; appuyer sur Entrée ne crée pas de nouveau paragraphe.

\vspace{4pt}
C'est le \textbf{balisage} qui produit la mise en forme : un nouveau paragraphe s'obtient avec un nouveau \texttt{<p>}, les espacements avec du CSS (semaine 4).
\end{tcolorbox}

\begin{lstlisting}[language=HTML5, caption={Un commentaire n'est pas affiché dans la page}]
<!-- Liste des sujets du forum - à remplacer par du contenu
     généré en JavaScript à partir de la semaine 7 -->
<ul>
  <li>Bienvenue sur le MiniForum</li>
</ul>
\end{lstlisting}

\begin{tcolorbox}[astuce, title={Le commentaire n'est pas un secret}]
Un commentaire HTML est invisible \textit{dans la page}, mais parfaitement lisible par n'importe qui via \textit{Afficher le code source} (\texttt{Ctrl+U}). Il sert à expliquer ton code, jamais à y cacher une information.
\end{tcolorbox}

\section{La structure d'un document HTML5}
% ============================================================

Toute page HTML5 repose sur le même squelette. Il est à connaître par c\oe ur :

\begin{lstlisting}[language=HTML5, caption={Squelette minimal d'une page HTML5}]
<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>MiniForum</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- Tout le contenu visible de la page -->
</body>
</html>
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{3.6cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Élément} & \hdr{Rôle} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{<!DOCTYPE html>} & Annonce au navigateur qu'il s'agit d'un document HTML5. Sans lui, le navigateur bascule dans un mode de compatibilité imprévisible \\
  \texttt{<html lang="fr">} & La racine du document ; \texttt{lang} indique la langue du contenu \\
  \rowcolor{uniPaper}
  \texttt{<head>} & Métadonnées \textbf{invisibles} : encodage, titre d'onglet, feuilles de style \\
  \texttt{<body>} & Tout le contenu \textbf{visible} de la page \\
  \bottomrule
\end{tabularx}
\end{center}

\subsection{Ce que contient le \texttt{<head>}}

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{4.3cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Balise} & \hdr{Ce qu'elle fait} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{<meta charset="UTF-8">} & Définit l'encodage des caractères. \textbf{Toujours UTF-8} : sans cette ligne, les accents s'affichent en caractères illisibles \\
  \texttt{<meta name="viewport">} & Indique au téléphone d'afficher la page à sa taille réelle. Indispensable pour le responsive (semaine 5) \\
  \rowcolor{uniPaper}
  \texttt{<title>} & Le texte affiché dans l'onglet, dans les favoris et dans les résultats de recherche \\
  \texttt{<meta name="description">} & Le résumé affiché sous le titre dans les résultats des moteurs de recherche \\
  \rowcolor{uniPaper}
  \texttt{<link rel="stylesheet">} & Rattache une feuille de style CSS externe \\
  \bottomrule
\end{tabularx}
\end{center}

\begin{tcolorbox}[attention, title={\texttt{<head>} et \texttt{<body>} : ne pas confondre}]
Tout ce qui doit être \textbf{vu} par le visiteur va dans le \texttt{<body>}. Le \texttt{<head>} ne contient que des informations \textit{sur} la page. Un titre écrit dans le \texttt{<head>} n'apparaîtra jamais dans la page --- c'est l'erreur de débutant la plus courante de la semaine.
\end{tcolorbox}

\begin{tcolorbox}[astuce, title={Gagner du temps dans VS Code}]
Dans un fichier \texttt{.html} vide, tape \texttt{!} puis \texttt{Tab} : VS Code génère l'intégralité du squelette ci-dessus. Utilise ce raccourci --- mais assure-toi de savoir le réécrire à la main, car c'est ce qui sera demandé au contrôle écrit de la semaine 12.
\end{tcolorbox}

\section{Les éléments sémantiques}
% ============================================================

Pendant longtemps, les pages web ont été construites avec des \texttt{<div>} partout : des boîtes sans signification, distinguées uniquement par leur nom de classe. HTML5 a introduit des balises \textbf{sémantiques}, qui décrivent le \textbf{rôle} de chaque zone.

\begin{tcolorbox}[definition, title={Définition --- Sémantique}]
Une balise \textbf{sémantique} indique ce que le contenu \textit{est}, pas la façon dont il doit s'afficher. \texttt{<nav>} signifie « ceci est une zone de navigation », indépendamment de sa couleur ou de sa position.
\end{tcolorbox}

\vspace{4pt}
\noindent\textbf{Trois publics en tirent parti :}

\begin{itemize}
  \item les \textbf{humains} qui relisent le code --- toi, dans trois semaines, ou un collègue ;
  \item les \textbf{moteurs de recherche}, qui comprennent où se trouve le contenu principal ;
  \item les \textbf{lecteurs d'écran}, qui permettent aux personnes malvoyantes de sauter directement à la navigation ou au contenu. C'est le sujet de la semaine 3.
\end{itemize}

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{2.6cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Balise} & \hdr{Quand l'utiliser} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{<header>} & En-tête de la page \textbf{ou} d'une section : titre, logo, date de publication \\
  \texttt{<nav>} & Un ensemble de liens de navigation. Réservé aux menus principaux, pas au moindre lien isolé \\
  \rowcolor{uniPaper}
  \texttt{<main>} & Le contenu principal. \textbf{Un seul par page}, et il ne contient ni en-tête ni menu \\
  \texttt{<section>} & Un regroupement thématique, normalement introduit par un titre \\
  \rowcolor{uniPaper}
  \texttt{<article>} & Un contenu autonome : un message du forum, un billet de blog \\
  \texttt{<aside>} & Un contenu annexe, secondaire par rapport au contenu principal \\
  \rowcolor{uniPaper}
  \texttt{<footer>} & Pied de page de la page ou d'une section \\
  \bottomrule

\begin{tcolorbox}[astuce, title={\texttt{<section>} ou \texttt{<article>} ?}]
Le test : est-ce que ce contenu garderait du sens \textbf{sorti de la page}, publié seul ailleurs ?

\vspace{3pt}
Si oui, c'est un \texttt{<article>} --- un message de forum que l'on pourrait citer sur un autre site. Si non, c'est une \texttt{<section>} --- « Sujets récents » n'a de sens que dans le forum qui la contient.
\end{tcolorbox}

\subsection{Ce qui reste du \texttt{<div>}}

Les \texttt{<div>} et \texttt{<span>} n'ont pas disparu ; ils ont simplement cessé d'être le choix par défaut.

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{2cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Balise} & \hdr{Usage légitime} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{<div>} & Regrouper des éléments \textbf{uniquement} pour les mettre en forme, sans aucune signification à exprimer \\
  \texttt{<span>} & Idem, mais à l'intérieur d'une ligne de texte (pour colorer un mot, par exemple) \\
  \bottomrule
\end{tabularx}
\end{center}

\begin{tcolorbox}[attention, title={Une balise sémantique ne change (presque) rien à l'affichage}]
Remplacer un \texttt{<div>} par un \texttt{<main>} ne modifie pas visiblement la page. C'est déroutant au début : on a l'impression que le choix n'a pas d'importance.

\vspace{3pt}
Il en a une, mais elle est \textbf{invisible} --- elle se joue du côté des lecteurs d'écran, des moteurs de recherche et de la lisibilité du code. C'est aussi pour cela que le TP de cette semaine se fait \textbf{sans CSS} : rien ne doit venir masquer la structure.
\end{tcolorbox}

\subsection{Titres et paragraphes}

\begin{lstlisting}[language=HTML5, caption={Titres et texte}]
<h1>MiniForum</h1>
<h2>Sujets récents</h2>
<h3>Bienvenue sur le forum</h3>

<p>Un paragraphe de texte, dans lequel on peut signaler du
   <strong>contenu important</strong> ou mettre un mot en
   <em>emphase</em>.</p>
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{2.4cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Balise} & \hdr{Sens} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{<h1>}\dots\texttt{<h6>} & Six niveaux de titres, du plus important au plus fin \\
  \texttt{<p>} & Un paragraphe de texte \\
  \rowcolor{uniPaper}
  \texttt{<strong>} & Contenu d'\textbf{importance forte} (s'affiche en gras) \\
  \texttt{<em>} & \textit{Emphase}, mot sur lequel on insiste (s'affiche en italique) \\
  \rowcolor{uniPaper}
  \texttt{<br>} & Retour à la ligne \textbf{à l'intérieur} d'un paragraphe (une adresse postale, un vers) \\
  \texttt{<blockquote>} & Une citation longue, extraite d'une autre source \\
  \bottomrule
\end{tabularx}
\end{center}

\begin{tcolorbox}[attention, title={\texttt{<strong>} plutôt que \texttt{<b>}, \texttt{<em>} plutôt que \texttt{<i>}}]
\texttt{<b>} et \texttt{<i>} décrivent une \textit{apparence} (gras, italique) ; \texttt{<strong>} et \texttt{<em>} décrivent un \textit{sens}. Le rendu est identique, mais un lecteur d'écran change d'intonation sur un \texttt{<strong>} et ignore un \texttt{<b>}.

\vspace{3pt}
La règle générale du HTML est là tout entière : \textbf{choisir la balise selon le sens}, et laisser le CSS s'occuper de l'apparence.
\end{tcolorbox}

\subsection{La hiérarchie des titres}

Les titres ne sont pas un outil de mise en forme : ils construisent le \textbf{plan} du document, exactement comme les niveaux de titres d'un rapport.

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{XX}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Plan correct} & \hdr{Plan incorrect} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{h1} MiniForum & \texttt{h1} MiniForum \\
  \rowcolor{uniPaper}
  \quad\texttt{h2} Sujets récents & \quad\texttt{h3} Sujets récents \quad\textcolor{alertRed}{\textbf{(saut de niveau)}} \\
  \rowcolor{uniPaper}
  \quad\quad\texttt{h3} Bienvenue & \quad\quad\texttt{h2} Bienvenue \\
  \rowcolor{uniPaper}
  \quad\quad\texttt{h3} Installer Node.js & \texttt{h1} Nouveau sujet \quad\textcolor{alertRed}{\textbf{(deuxième h1)}} \\
  \rowcolor{uniPaper}
  \quad\texttt{h2} Nouveau sujet & \\
  \bottomrule
\end{tabularx}
\end{center}

\vspace{4pt}
Deux règles suffisent : \textbf{un seul \texttt{<h1>} par page}, et \textbf{on ne saute pas de niveau} en descendant. Choisir un \texttt{<h3>} parce qu'il « fait la bonne taille » est une erreur : la taille se règle en CSS.

\subsection{Éléments en bloc et éléments en ligne}

\begin{tcolorbox}[definition, title={Définition --- Bloc et en ligne}]
Un élément \textbf{en bloc} occupe toute la largeur disponible et provoque un retour à la ligne : \texttt{<p>}, \texttt{<h1>}, \texttt{<ul>}, \texttt{<section>}, \texttt{<div>}.

\vspace{3pt}
Un élément \textbf{en ligne} se place dans le fil du texte, sans le couper : \texttt{<a>}, \texttt{<strong>}, \texttt{<em>}, \texttt{<img>}, \texttt{<span>}.
\end{tcolorbox}

Cette distinction explique dès maintenant pourquoi deux paragraphes se suivent verticalement alors que deux liens restent côte à côte. Elle deviendra centrale en semaine 4, avec le modèle de boîte du CSS.

\section{Liens et images}
% ============================================================

\subsection{Le lien hypertexte}

Le lien est ce qui fait du web un web. Il se crée avec la balise \texttt{<a>} (\textit{anchor}) et son attribut \texttt{href}.

\begin{lstlisting}[language=HTML5, caption={Quatre types de liens}]
<!-- Lien externe : URL complète -->
<a href="https://www.hepia.ch">Site de la hepia</a>

<!-- Lien interne au site : vers un autre fichier -->
<a href="sujet.html">Voir le sujet</a>

<!-- Lien vers un élément de la page courante -->
<a href="#nouveau-sujet">Créer un sujet</a>

<!-- Lien ouvrant un nouvel onglet -->
<a href="https://developer.mozilla.org" target="_blank">MDN</a>
\end{lstlisting}

\begin{tcolorbox}[astuce, title={Écrire un bon intitulé de lien}]
Le texte du lien doit décrire sa destination \textbf{hors contexte}. Les lecteurs d'écran proposent en effet de lister tous les liens d'une page : une liste de « cliquez ici » répétés n'informe personne.

\vspace{3pt}
\textcolor{successGreen}{\textbf{OUI}}\quad \texttt{<a href="sujet.html">Lire le sujet complet</a>}\\[3pt]
\textcolor{alertRed}{\textbf{NON}}\quad \texttt{<a href="sujet.html">cliquez ici</a>}
\end{tcolorbox}

\subsection{Chemins relatifs et chemins absolus}

C'est la source d'erreur numéro un du TP : l'image ne s'affiche pas, le lien ne mène nulle part. Presque toujours, le chemin est en cause.

\begin{lstlisting}[caption={Arborescence du projet MiniForum}]
miniforum/
  |-- index.html
  |-- sujet.html
  |-- style.css
  \-- images/
       \-- logo.png
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{4.2cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Écriture} & \hdr{Signification} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{sujet.html} & Un fichier du \textbf{même dossier} \\
  \texttt{images/logo.png} & Le fichier \texttt{logo.png}, dans le sous-dossier \texttt{images} \\
  \rowcolor{uniPaper}
  \texttt{../style.css} & Remonter d'un dossier, puis prendre \texttt{style.css} \\
  \texttt{https://\dots} & Une adresse \textbf{absolue}, sur un autre serveur \\
  \bottomrule
\end{tabularx}
\end{center}

\begin{tcolorbox}[attention, title={Trois pièges classiques}]
\begin{itemize}
  \item \textbf{La casse compte.} \texttt{Logo.png} et \texttt{logo.png} sont deux fichiers différents pour un serveur Linux --- même si Windows ne fait pas la différence. Ta page marchera chez toi et cassera en ligne.
  \item \textbf{Pas d'espaces ni d'accents} dans les noms de fichiers : écris \texttt{photo-profil.png}, jamais \texttt{photo profil.png} ni \texttt{été.jpg}.
  \item \textbf{Jamais de chemin \texttt{C:/Users/\dots}} : ce chemin n'existe que sur ta machine. Tous les chemins d'un site sont relatifs au projet.
\end{itemize}
\end{tcolorbox}

\subsection{L'attribut \texttt{id}}

L'attribut \texttt{id} donne un \textbf{nom unique} à un élément de la page. Le lien \texttt{href="\#nouveau-sujet"} vu plus haut ne pointe pas vers un fichier, mais vers l'élément qui porte cet identifiant.

\begin{lstlisting}[language=HTML5, caption={Un id sert de cible à un lien interne}]
<a href="#nouveau-sujet">Créer un sujet</a>

<!-- ... plus bas dans la page ... -->
<section id="nouveau-sujet">
  <h2>Créer un nouveau sujet</h2>
</section>
\end{lstlisting}

\begin{tcolorbox}[attention, title={Règle d'or --- un \texttt{id} est unique dans la page}]
Deux éléments ne peuvent \textbf{jamais} partager le même \texttt{id} : c'est ce qui garantit qu'un \texttt{id} désigne un élément, et un seul. Le validateur W3C signale d'ailleurs les doublons comme des erreurs.
\end{tcolorbox}

\begin{tcolorbox}[astuce, title={L'\texttt{id}, un point d'accroche pour toute l'année}]
L'\texttt{id} ne sert pas qu'aux liens internes. C'est le point d'accroche universel vers un élément : il reliera un \texttt{<label>} à son champ (semaine 3), permettra de cibler un élément en \textbf{CSS} (semaine 4), et de le manipuler en \textbf{JavaScript} (semaine 7). Souviens-toi du premier exemple de la semaine 1 : \texttt{document.getElementById('btn')} allait chercher le bouton par son \texttt{id}.
\end{tcolorbox}

\subsection{Les images}

\begin{lstlisting}[language=HTML5, caption={Insérer une image, avec ou sans légende}]
<img src="images/logo.png" alt="Logo du MiniForum">

<figure>
  <img src="images/schema-forum.png"
       alt="Schéma des pages du forum et de leurs liens">
  <figcaption>Organisation des pages du MiniForum</figcaption>
</figure>
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{2.6cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Attribut} & \hdr{Rôle} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{src} & Le chemin vers le fichier image (\textit{source}) \\
  \texttt{alt} & Le texte alternatif décrivant l'image \\
  \rowcolor{uniPaper}
  \texttt{width} / \texttt{height} & Dimensions en pixels ; les renseigner évite que la page « saute » pendant le chargement \\
  \bottomrule
\end{tabularx}
\end{center}

\begin{tcolorbox}[attention, title={L'attribut \texttt{alt} n'est pas optionnel}]
Le texte \texttt{alt} est lu à voix haute par les lecteurs d'écran et s'affiche si l'image ne charge pas. Le validateur W3C signale son absence comme une erreur.

\vspace{4pt}
\textcolor{successGreen}{\textbf{OUI}}\quad \texttt{alt="Logo du MiniForum"}\\[3pt]
\textcolor{alertRed}{\textbf{NON}}\quad \texttt{alt="image"} \quad ou \quad \texttt{alt="photo de logo.png"}

\vspace{4pt}
Cas particulier : une image purement décorative, qui n'apporte aucune information, prend un \texttt{alt} \textbf{vide} --- \texttt{alt=""} --- pour que le lecteur d'écran l'ignore au lieu d'annoncer le nom du fichier. On approfondira en semaine 3.
\end{tcolorbox}

\section{Listes et tableaux}

\subsection{Les listes}

\begin{lstlisting}[language=HTML5, caption={Liste non ordonnée et liste ordonnée}]
<!-- Liste à puces : l'ordre est indifférent -->
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

<!-- Liste numérotée : l'ordre compte -->
<ol>
  <li>Ouvrir le terminal</li>
  <li>Taper la commande</li>
  <li>Valider</li>
</ol>
\end{lstlisting}

\begin{tcolorbox}[attention, title={Un \texttt{<li>} vit toujours dans un \texttt{<ul>} ou un \texttt{<ol>}}]
Rien d'autre qu'un \texttt{<li>} ne peut être enfant direct d'un \texttt{<ul>} --- pas de \texttt{<p>}, pas de \texttt{<div>}. Ce contenu doit être placé \textit{à l'intérieur} du \texttt{<li>}. Le validateur est intraitable sur ce point.

\vspace{3pt}
Une liste peut en revanche en contenir une autre : la sous-liste se place \textbf{dans} le \texttt{<li>} parent, avant sa fermeture.
\end{tcolorbox}

\begin{tcolorbox}[astuce, title={Un menu de navigation est une liste de liens}]
Les barres de navigation s'écrivent presque toujours ainsi : un \texttt{<nav>} contenant un \texttt{<ul>} de liens. Cela paraît étrange tant qu'on pense en termes d'apparence --- mais un menu \textit{est} bien une liste, et le CSS se chargera plus tard de l'afficher horizontalement.
\end{tcolorbox}

\subsection{Les tableaux}

Un tableau se construit ligne par ligne (\texttt{<tr>}), avec des cellules d'en-tête (\texttt{<th>}) et des cellules de données (\texttt{<td>}).

\begin{lstlisting}[language=HTML5, caption={Un tableau complet}]
<table>
  <caption>Derniers sujets publiés</caption>
  <thead>
    <tr>
      <th>Sujet</th>
      <th>Auteur</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Bienvenue</td>
      <td>Alice</td>
    </tr>
    <tr>
      <td>Installer Node.js</td>
      <td>Bob</td>
    </tr>
  </tbody>
</table>
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{2.4cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Balise} & \hdr{Rôle} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{<caption>} & Le titre du tableau ; première balise à l'intérieur de \texttt{<table>} \\
  \texttt{<thead>} / \texttt{<tbody>} & Séparent la ligne d'en-tête du corps des données \\
  \rowcolor{uniPaper}
  \texttt{<tr>} & Une ligne (\textit{table row}) \\
  \texttt{<th>} & Une cellule d'en-tête (\textit{table header}) \\
  \rowcolor{uniPaper}
  \texttt{<td>} & Une cellule de données (\textit{table data}) \\
  \bottomrule
\end{tabularx}
\end{center}

\subsubsection*{Fusionner des cellules}

\begin{lstlisting}[language=HTML5, caption={Fusion horizontale avec colspan}]
<tr>
  <th colspan="2">Coordonnées</th>
</tr>
<tr>
  <td>E-mail</td>
  <td>alice@exemple.ch</td>
</tr>
\end{lstlisting}

La cellule « Coordonnées » occupe la largeur de \textbf{deux} colonnes grâce à \texttt{colspan="2"}. L'attribut \texttt{rowspan="2"} produit le même effet sur la hauteur, en fusionnant deux lignes.

\begin{tcolorbox}[interdit, title={Un tableau sert à présenter des données, jamais à mettre en page}]
Un \texttt{<table>} présente des \textbf{données tabulaires} : un horaire, un relevé de notes, une comparaison. Il ne doit \textbf{jamais} servir à positionner des éléments dans la page --- c'est le rôle du CSS, vu en semaines 4 et 5. Une page mise en page avec des tableaux est illisible pour un lecteur d'écran et impossible à rendre responsive.
\end{tcolorbox}

\section{Valider son HTML}
% ============================================================

Le navigateur est très tolérant : il affiche une page même si des balises sont mal fermées, en devinant ce qu'on a voulu écrire. Cette tolérance est un piège --- chaque navigateur devine à sa manière, et le jour où l'affichage se dérègle, l'erreur est déjà enfouie sous cent lignes de code.

\begin{tcolorbox}[definition, title={Le validateur du W3C}]
Le service \textbf{validator.w3.org} vérifie qu'une page respecte la spécification HTML5. Il propose trois modes : par \textbf{adresse} (page en ligne), par \textbf{fichier} téléversé, ou par \textbf{copier-coller} du code --- c'est ce dernier mode que tu utiliseras en TP.
\end{tcolorbox}

\subsection{Lire un message d'erreur}

Chaque message du validateur comporte trois parties : la \textbf{ligne et la colonne} concernées, la \textbf{description} de l'erreur, et un \textbf{extrait} du code fautif avec la position surlignée.

\begin{tcolorbox}[corrige, title={Exemple de message}]
\ttfamily\small
Error: End tag \textcolor{alertRed}{section} seen, but there were open elements.\\
From line 24, column 3; to line 24, column 12
\end{tcolorbox}

\vspace{4pt}
Traduction : à la ligne 24, on ferme une \texttt{<section>} alors qu'un élément ouvert à l'intérieur ne l'a pas été. Il manque une balise fermante quelque part au-dessus.

\begin{center}
\renewcommand{\arraystretch}{1.0}
\begin{tabularx}{\linewidth}{p{5.4cm}X}
  \toprule
  \rowcolor{uniNavy}
  \hdr{Message fréquent} & \hdr{Ce qu'il faut corriger} \\
  \midrule
  \rowcolor{uniPaper}
  \texttt{End tag X seen, but there were open elements} & Une balise ouverte à l'intérieur n'a pas été fermée \\
  \texttt{Unclosed element X} & La balise \texttt{X} n'est jamais fermée \\
  \rowcolor{uniPaper}
  \texttt{Duplicate ID "xyz"} & Deux éléments portent le même \texttt{id} \\
  \texttt{An img element must have an alt attribute} & Une image sans \texttt{alt} \\
  \rowcolor{uniPaper}
  \texttt{Element X not allowed as child of element Y} & Mauvaise imbrication (un \texttt{<p>} directement dans un \texttt{<ul>}, par exemple) \\
  \texttt{Consider adding a lang attribute} & Il manque \texttt{lang="fr"} sur la balise \texttt{<html>} \\
  \rowcolor{uniPaper}
  \texttt{Stray end tag X} & Une balise fermante sans ouvrante correspondante \\
  \bottomrule
\end{tabularx}
\end{center}

\begin{tcolorbox}[astuce, title={Méthode --- corriger de haut en bas}]
Une seule balise oubliée peut produire dix messages d'erreur en cascade. Corrige donc \textbf{la première erreur de la liste}, puis relance la validation : le nombre d'erreurs chute souvent d'un coup.

\vspace{3pt}
Distingue aussi les \textbf{Errors} (rouge), qui doivent toutes disparaître, des \textbf{Warnings} (jaune), qui signalent une maladresse sans invalider la page.
\end{tcolorbox}

\begin{tcolorbox}[astuce, title={Prévenir plutôt que corriger}]
Trois habitudes suppriment la majorité des erreurs avant même la validation :
\begin{itemize}
  \item \textbf{indenter} systématiquement (\texttt{Maj+Alt+F} dans VS Code, avec Prettier) ;
  \item écrire la balise \textbf{fermante immédiatement} après l'ouvrante, puis remplir le contenu ;
  \item se fier au \textbf{soulignement rouge} de VS Code, qui repère déjà une partie des erreurs.
\end{itemize}
\end{tcolorbox}

% ============================================================
\section*{Résumé de la semaine}
% ============================================================

\begin{tcolorbox}[definition, title={Ce qu'il faut retenir}]
\begin{itemize}
  \item HTML est un langage de \textbf{balisage} : il décrit la structure, pas l'apparence
  \item Les balises s'\textbf{imbriquent} comme des parenthèses et forment un \textbf{arbre}
  \item Toute page suit le même squelette : \texttt{<!DOCTYPE>}, \texttt{<html lang>}, \texttt{<head>}, \texttt{<body>}
  \item Le \texttt{<head>} contient les métadonnées invisibles ; le \texttt{<body>}, tout le visible
  \item Les balises \textbf{sémantiques} (\texttt{<header>}, \texttt{<nav>}, \texttt{<main>}, \texttt{<article>}, \texttt{<footer>}) décrivent le rôle de chaque zone
  \item \textbf{Un seul \texttt{<h1>}} par page, et pas de saut de niveau dans les titres
  \item Un \texttt{id} est \textbf{unique} ; un \texttt{alt} est \textbf{obligatoire} sur chaque image
  \item Les tableaux servent à des \textbf{données}, jamais à la mise en page
  \item Une page se \textbf{valide} sur \texttt{validator.w3.org}, et les erreurs se corrigent de haut en bas
\end{itemize}
\end{tcolorbox}
