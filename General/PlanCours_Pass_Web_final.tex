\section{Présentation générale}
% ============================================================

Ce cours constitue le volet \textbf{développement web} du programme de la classe passerelle. Il a pour objectif de faire acquérir aux étudiant·e·s les compétences nécessaires à la réalisation d'une application web dynamique complète, de la mise en forme d'une page HTML jusqu'à la persistance des données en base de données relationnelle.

Le public visé est composé de titulaires d'un baccalauréat général français, pour la grande majorité sans expérience préalable en informatique. La progression est construite en conséquence : les concepts fondamentaux (variables, conditions, boucles, fonctions) sont introduits progressivement, le retour visuel immédiat dans le navigateur servant de moteur de motivation en début de parcours.

\medskip
\noindent\textbf{Cours parallèles à prendre en compte :}
\begin{itemize}
  \item \textbf{Programmation orientée objet (C\#)} — les concepts de variable, boucle, fonction et structure de contrôle y sont couverts ; ce cours peut donc s'appuyer sur ces acquis pour accélérer la partie algorithmique en JavaScript.
  \item \textbf{Linux / programmation Bash} — les étudiant·e·s sont à l'aise dans un terminal ; cela rend l'environnement Node.js naturel et cohérent.
\end{itemize}

\medskip
\noindent\textbf{Choix de stack :} JavaScript est utilisé à la fois côté client (navigateur) et côté serveur (Node.js / Express), ce qui réduit la charge cognitive liée à l'apprentissage simultané de deux langages. MySQL/MariaDB est utilisé comme SGBDR. Aucun framework front-end n'est introduit : HTML, CSS et JavaScript vanilla uniquement, afin de garantir la compréhension des mécanismes fondamentaux.

% ============================================================
\section{Compétences visées}
% ============================================================

À l'issue de ce cours, les étudiant·e·s seront capables de :

\begin{itemize}
  \item Structurer une page web sémantique en HTML5 et la mettre en forme avec CSS (Flexbox, responsive design)
  \item Écrire des scripts JavaScript (ES6+) pour manipuler le DOM et réagir aux événements utilisateur
  \item Consommer une API REST depuis le navigateur avec \texttt{fetch} et le format JSON
  \item Concevoir un modèle de données relationnel (MCD → MLD) à partir d'un besoin métier
  \item Écrire des requêtes SQL incluant jointures, agrégations et sous-requêtes
  \item Construire un serveur web avec Node.js / Express exposant des routes REST
  \item Connecter un serveur Node.js à une base MySQL via des requêtes paramétrées
  \item Implémenter un CRUD complet (Create, Read, Update, Delete) côté serveur
  \item Mettre en œuvre une authentification sécurisée (hashage de mots de passe, sessions)
  \item Protéger une application contre les injections SQL et le XSS de base
  \item Présenter oralement un projet technique avec démonstration fonctionnelle
\end{itemize}

\section{Le projet fil rouge : MiniForum}
% ============================================================

Plutôt que des exercices isolés par technologie, l'ensemble du cours est structuré autour d'un projet unique qui évolue de semaine en semaine : \textbf{MiniForum}, un forum simplifié comportant des utilisateurs, des sujets de discussion (\textit{topics}), des messages (\textit{posts}) et des réactions (\textit{likes}).

Ce périmètre fonctionnel est volontairement restreint, mais suffisamment riche pour illustrer les relations \textit{one-to-many} (un utilisateur a plusieurs messages) et \textit{many-to-many} (un message peut être aimé par plusieurs utilisateurs).

\subsection{Progression en quatre phases}

\begin{center}
\begin{tabularx}{\linewidth}{clXc}
  \toprule
  \rowcolor{accentBlue}
  \color{white}\textbf{Phase} &
  \color{white}\textbf{Semaines} &
  \color{white}\textbf{Thème} &
  \color{white}\textbf{Volume} \\
  \midrule
  \rowcolor{cfptGrey}
  1 & 1–5  & HTML/CSS/JS — affichage statique, données en mémoire & 40h \\
  2 & 6–8  & SQL — modélisation et requêtes sur base pré-remplie & 24h \\
  \rowcolor{cfptGrey}
  3 & 9–13 & Node.js/Express — API REST branchée sur MySQL & 40h \\
  4 & 14–15 & Authentification, sécurité, soutenance & 16h \\
  \bottomrule
\end{tabularx}
\end{center}

La \textbf{frustration volontaire} de la phase 1 — les données disparaissent au rafraîchissement — est le principal levier de motivation pour l'introduction de la persistance en base de données.

\begin{tcolorbox}[colback=accentBlue!8, colframe=accentBlue, boxrule=0.6pt, arc=3pt]

% ---- PHASE 2 ----
\subsection{Phase 2 — Bases de données \& SQL (semaines 6 à 8)}

\begin{tcolorbox}[colback=accentBlue!8, colframe=accentBlue, boxrule=0.6pt, arc=3pt]
\small Avant d'introduire le serveur, les étudiant·e·s acquièrent les bases du modèle relationnel et de SQL sur une base pré-remplie fournie par l'enseignante. L'objectif est de maîtriser les requêtes avant de les écrire dans du code.
\end{tcolorbox}
\vspace{6pt}

% S6
\semainetitre{6}{Modélisation relationnelle (MCD / MLD)}{4h cours / 4h TP}
\begin{tcolorbox}[semaine]
\begin{tcolorbox}[objectifs]
\begin{itemize}
  \item Identifier entités, attributs et relations d'un système d'information
  \item Construire un diagramme de classes UML et le transformer en MLD
  \item Distinguer relations one-to-many et many-to-many afin de comprendre la table de liaison
\end{itemize}
\end{tcolorbox}
\vspace{4pt}
\contenutitre{Cours}
\begin{itemize}
  \item Notions de SGBDR, table, ligne, colonne, clé primaire, clé étrangère
  \item Notation UML : multiplicités \texttt{1}, \texttt{0..1}, \texttt{1..*}, \texttt{0..*}
  \item Relation one-to-many (\texttt{1..*}) : un utilisateur a plusieurs messages
  \item Relation many-to-many (\texttt{0..*} / \texttt{0..*}) : un message peut être aimé par plusieurs utilisateurs
  \item Du diagramme UML au MLD : règles de transformation, tables de liaison
  \item Introduction à MySQL/MariaDB : installation, phpMyAdmin ou client terminal
\end{itemize}
\contenutitre{Travaux pratiques}
\begin{itemize}
  \item Construction collective du diagramme de classes UML du MiniForum
  \item Transformation en MLD : identification des tables de liaison
  \item Création des tables dans MySQL à partir du MLD
\end{itemize}
\end{tcolorbox}
\begin{tcolorbox}[filrouge={Schéma officiel du forum}]
\small Le diagramme de classes UML du MiniForum est construit collectivement, puis transformé en MLD avec sa table de liaison \texttt{likes}. Ce schéma \texttt{users / topics / posts / likes} sera
la référence jusqu'à la fin du cours. Les étudiant·e·s créent eux-mêmes
les tables dans MySQL.
\end{tcolorbox}
\vspace{8pt}

% S7
\semainetitre{7}{SQL — Interrogation \& jointures}{4h cours / 4h TP}
\begin{tcolorbox}[semaine]
\begin{tcolorbox}[objectifs]
\begin{itemize}
  \item Écrire des requêtes SQL de lecture avec filtres, tris et agrégations
  \item Utiliser \texttt{INNER JOIN} et \texttt{LEFT JOIN} pour croiser plusieurs tables
\end{itemize}
\end{tcolorbox}
\vspace{4pt}
\contenutitre{Cours}
\begin{itemize}
  \item \texttt{SELECT}, \texttt{WHERE}, \texttt{ORDER BY}, \texttt{LIMIT}
  \item Fonctions d'agrégation : \texttt{COUNT}, \texttt{SUM}, \texttt{AVG}, \texttt{GROUP BY}, \texttt{HAVING}
  \item \texttt{INNER JOIN} et \texttt{LEFT JOIN} avec alias de table
  \item Bonnes pratiques de lisibilité SQL
\end{itemize}
\contenutitre{Travaux pratiques}
\begin{itemize}
  \item Requêtes progressives sur la base MiniForum pré-remplie (phpMyAdmin ou terminal)
  \item Lister les sujets les plus récents, compter les messages par utilisateur, retrouver les messages d'un sujet avec l'auteur
\end{itemize}
\end{tcolorbox}
\begin{tcolorbox}[filrouge={Interroger les vraies données du forum}]
\small La base MiniForum contient 10 utilisateurs, 20 sujets et 80 messages fictifs. Les étudiant·e·s écrivent des requêtes qui retourneraient exactement ce qu'afficherait leur page d'accueil — la passerelle vers la phase suivante est évidente.
\end{tcolorbox}

\subsection{Phase 3 — Node.js / Express \& API REST (semaines 9 à 13)}

\begin{tcolorbox}[colback=accentBlue!8, colframe=accentBlue, boxrule=0.6pt, arc=3pt]
\small C'est la phase la plus dense techniquement. Les étudiant·e·s construisent le serveur qui manquait depuis la phase 1, et branchent progressivement leur front-end dessus. Le JavaScript appris en semaine 5 est immédiatement réutilisable côté serveur.

% S9
\semainetitre{9}{JavaScript asynchrone \& Node.js}{4h cours / 4h TP}
\begin{tcolorbox}[semaine]
\begin{tcolorbox}[objectifs]
\begin{itemize}
  \item Comprendre la nature asynchrone de JavaScript et son modèle d'exécution
  \item Écrire du code asynchrone lisible avec \texttt{async}/\texttt{await}
  \item Exécuter JavaScript hors navigateur avec Node.js
\end{itemize}
\end{tcolorbox}
\vspace{4pt}
\contenutitre{Cours}
\begin{itemize}
  \item Synchrone vs asynchrone : pourquoi JavaScript a besoin de Promises
  \item Promises : états (\textit{pending}, \textit{fulfilled}, \textit{rejected}), \texttt{then}/\texttt{catch}
  \item Syntaxe \texttt{async}/\texttt{await} et équivalence avec les Promises
  \item Gestion des erreurs : \texttt{try}/\texttt{catch} en contexte asynchrone
  \item Node.js : installation, \texttt{npm init}, \texttt{npm install}, scripts \texttt{package.json}
\end{itemize}
\contenutitre{Travaux pratiques}
\begin{itemize}
  \item Simulation de délai avec \texttt{setTimeout} encapsulé dans une Promise
  \item Réécriture du même traitement en \texttt{then/catch} puis \texttt{async/await}
  \item Premier script Node.js exécuté dans le terminal
\end{itemize}
\end{tcolorbox}
\begin{tcolorbox}[filrouge={Simuler l'appel serveur}]
\small Une fonction asynchrone fictive retourne les données du forum après un délai simulé. Le front-end est adapté pour attendre cette réponse avec \texttt{await} — syntaxe identique à ce qu'il utilisera avec \texttt{fetch} la semaine suivante.
\end{tcolorbox}

\begin{tcolorbox}[semaine]
\begin{tcolorbox}[objectifs]

  \item Valider les données entrantes côté serveur

% S14
\semainetitre{14}{Authentification — Inscription, connexion \& sessions}{6h cours / 6h TP}
\begin{tcolorbox}[semaine]
\begin{tcolorbox}[objectifs]
\begin{itemize}
  \item Implémenter l'inscription avec hashage de mot de passe (\texttt{bcrypt})
  \item Mettre en œuvre une authentification par session côté serveur
  \item Protéger des routes aux seuls utilisateurs connectés
  \item Comprendre les risques XSS et injections SQL et comment les prévenir
\end{itemize}
\end{tcolorbox}
\vspace{4pt}
\contenutitre{Cours}
\begin{itemize}
  \item Risques liés au stockage de mots de passe en clair — exemples réels
  \item Hashage avec salage : principe de \texttt{bcrypt} et mise en œuvre
  \item Sessions côté serveur : \texttt{express-session}, cookies, durée de vie
  \item Middleware d'authentification pour protéger des routes
  \item XSS : principe, démonstration, prévention (\texttt{textContent} vs \texttt{innerHTML})
  \item Rappel injections SQL : requêtes paramétrées (déjà vu en semaine 11)
\end{itemize}
\contenutitre{Travaux pratiques}
\begin{itemize}
  \item Routes \texttt{POST /register} (hashage bcrypt) et \texttt{POST /login} (vérification + session)
  \item Route \texttt{POST /logout} et middleware de protection
  \item Protection des routes POST du forum aux seuls utilisateurs connectés
\end{itemize}
\end{tcolorbox}
\begin{tcolorbox}[filrouge={Seuls les membres peuvent poster}]
\small Le MiniForum dispose d'une vraie inscription et d'une vraie connexion. Seuls les utilisateurs authentifiés peuvent créer un sujet ou répondre. Chaque message affiche le nom de son auteur récupéré depuis la session.
\end{tcolorbox}
