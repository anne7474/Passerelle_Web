\section{S'organiser : arborescence et sauvegarde}
% ============================================================

Avant d'installer quoi que ce soit, on met en place une organisation de fichiers claire et une sauvegarde automatique. Tu ne perdras jamais ton travail, et tu retrouveras toujours facilement tes cours et projets.

\subsection{Créer l'arborescence des cours}

\begin{enumerate}
  \item Sur ton disque, ouvrir le répertoire \texttt{Documents}.
  \item Y créer un répertoire \texttt{Passerelle}.
  \item À l'intérieur de \texttt{Passerelle}, créer les trois sous-répertoires suivants :
\end{enumerate}

\subsection{Synchroniser automatiquement sur Google Drive}

Afin de ne pas perdre ton travail en cas de perte, de casse ou d'écrasement de disque, tu vas synchroniser automatiquement le répertoire \texttt{Passerelle} sur ton espace Google Drive personnel.

\paragraph{Étape 1 --- Mettre en place la synchronisation}

\begin{enumerate}
  \item Télécharger et installer \textbf{Drive pour ordinateur} : \url{https://workspace.google.com/intl/fr/products/drive/}
  \item Se connecter avec ton \textbf{compte eduge}.
  \item Appuyer deux fois sur \textit{Suivant}, jusqu'à l'étape de sélection du dossier à synchroniser.
  \item Cliquer sur \textbf{Ajouter un dossier}.
\end{enumerate}

\capture{images/Drive1.png}{Capture d'écran --- ajouter un dossier à synchroniser}

\begin{enumerate}[resume]
  \item Sélectionner le dossier \texttt{Passerelle} créé à l'étape précédente.
  \item Vérifier que \textbf{seul} le dossier \texttt{Passerelle} est coché, puis cliquer sur \textit{Suivant}.
  \item Continuer en appuyant sur \textit{Suivant}.
\end{enumerate}

\capture{images/Drive2.png}{Capture d'écran --- dossier Passerelle sélectionné}

\begin{tcolorbox}[attention, title={Attention}]
Ne synchronise que le dossier \texttt{Passerelle}. Ne coche pas \textit{Bureau}, \textit{Documents} ou \textit{Téléchargements} : tu risquerais de synchroniser bien plus que nécessaire et de saturer ton espace Drive.
\end{tcolorbox}

\paragraph{Étape 2 --- Vérifier le bon fonctionnement}

\begin{enumerate}
  \item Dans ton navigateur, aller sur ton \textbf{compte eduge} puis ouvrir \textbf{Drive}.
  \item Dans le Drive, cliquer sur \textit{Ordinateurs} $\rightarrow$ \textit{Mon ordinateur} $\rightarrow$ \texttt{Passerelle}.
  \item Tu dois retrouver l'arborescence créée sur ton ordinateur.
\end{enumerate}

\capture{images/Drive3.png}{Capture d'écran --- vérification de l'arborescence côté Drive}

\begin{enumerate}[resume]
  \item Créer un fichier \texttt{test.txt} sur ton ordinateur, dans le dossier \texttt{Web}.
  \item Vérifier qu'il apparaît bien côté Drive au bout de quelques secondes, puis le supprimer.
\end{enumerate}

\begin{tcolorbox}[astuce, title={C'est en place}]
Ton travail est désormais sauvegardé automatiquement. Attention toutefois : Google Drive est une \textbf{sauvegarde}, pas un outil de versionnage. C'est le rôle de Git, que tu mettras en place en section~4.
\end{tcolorbox}

\section{Installation des outils (Windows)}
% ============================================================

\subsection{Node.js}

\begin{enumerate}
  \item Aller sur \url{https://nodejs.org/fr/download} et télécharger la version \textbf{24 LTS} pour Windows (fichier \texttt{.msi}).
  \item Lancer l'installateur téléchargé, accepter la licence, cliquer sur \textit{Next}.
  \item Dossier de destination : garder celui proposé par défaut.
  \item Écran \textit{Custom Setup} : laisser toutes les cases cochées, en particulier \textbf{npm package manager} et \textbf{Add to PATH}.
\end{enumerate}

\begin{enumerate}[resume]
  \item Écran \textit{Tools for Native Modules} : laisser décoché (non nécessaire pour ce cours), cliquer sur \textit{Next}.
  \item Cliquer sur \textit{Install}, patienter, puis \textit{Finish}.
\end{enumerate}

\begin{tcolorbox}[attention, title={Vérification}]
\begin{enumerate}
  \item Ouvrir une invite de commande (\textit{cmd} ou \textit{PowerShell}).
    \capture[0.5\linewidth]{images/invit.png}{Capture d'écran --- ouvrir une invite de commande}
  \item Exécuter \texttt{node -v} puis \texttt{npm -v} : chaque commande doit afficher un numéro de version, et celui de Node doit commencer par \texttt{v24}.
    \capture[0.55\linewidth]{images/verif.png}{Capture d'écran --- vérification de l'installation de Node.js}
\end{enumerate}
\end{tcolorbox}

\begin{tcolorbox}[attention, title={Ne pas installer Node.js 20}]
Beaucoup de tutoriels en ligne proposent encore Node.js 20 : cette version est en fin de vie et ne doit plus être utilisée. Si \texttt{node -v} affiche autre chose que \texttt{v24}\ldots, désinstalle et recommence.
\end{tcolorbox}

\subsection{Git}

\begin{enumerate}
  \item Aller sur \url{https://git-scm.com/install/windows} et télécharger l'installateur proposé (la page détecte automatiquement l'architecture : c'est \texttt{x64} dans la quasi-totalité des cas).
  \item Lancer l'installateur, accepter la licence, garder le dossier de destination par défaut.
  \item Écran de sélection des composants : garder les cases cochées par défaut.
  \item Écran \textit{Choosing the default editor used by Git} : sélectionner \textbf{Visual Studio Code} dans la liste déroulante.
\end{enumerate}

\capture{images/Git1.png}{Capture d'écran --- choix de l'éditeur par défaut}

\begin{enumerate}[resume]
  \item Écran \textit{Adjusting the name of the initial branch} : choisir explicitement \textbf{main} comme nom de branche par défaut.
  \item Écran \textit{Adjusting your PATH environment} : garder l'option recommandée du milieu (\textit{Git from the command line and also from 3rd-party software}).
  \item Écran \textit{Choosing the SSH executable} : garder par défaut (\textit{Use bundled OpenSSH}).
  \item Écran \textit{Choosing HTTPS transport backend} : garder par défaut (\textit{Use the OpenSSL library}).
  \item Écran \textit{Configuring the line ending conversions} : garder l'option par défaut (\textit{Checkout Windows-style, commit Unix-style line endings}).
  \item Écrans suivants (\textit{terminal emulator}, \textit{git pull}, \textit{credential helper}) : garder les options par défaut proposées.
  \item Cliquer sur \textit{Install}, puis \textit{Finish}.
\end{enumerate}

\begin{tcolorbox}[attention, title={Vérification}]
Ouvrir une invite de commande et exécuter \texttt{git -{}-version} : la commande doit afficher un numéro de version.
\end{tcolorbox}

\subsection{Visual Studio Code}

\begin{enumerate}
  \item Aller sur \url{https://code.visualstudio.com} et télécharger la version Windows.
  \item Lancer l'installateur, accepter la licence, garder le dossier de destination par défaut.
  \item Écran \textit{Select Additional Tasks} : cocher \textbf{Add to PATH}, \textbf{Register Code as an editor for supported file types}, ainsi que les options \textit{Open with Code} du menu contextuel.
  \item Cliquer sur \textit{Install}, puis \textit{Finish} en laissant \textit{Launch Visual Studio Code} coché.
\end{enumerate}

\subsection{Désinstaller les extensions d'assistance IA}

\begin{tcolorbox}[interdit, title={Étape obligatoire du cours}]
Les assistants de génération de code sont \textbf{interdits} dans ce cours. Leur absence est vérifiée à chaque jalon. Les raisons sont expliquées en section~7 du polycopié.
\end{tcolorbox}

\begin{enumerate}
  \item Dans VS Code, ouvrir le panneau des extensions (\texttt{Ctrl+Shift+X}).
  \item Dans la barre de recherche, taper successivement : \texttt{copilot}, \texttt{ai}, \texttt{codeium}, \texttt{tabnine}.
  \item Pour chaque extension \textbf{installée} qui apparaît (GitHub Copilot, GitHub Copilot Chat, ou équivalent), cliquer sur l'engrenage puis \textit{Désinstaller}.
  \item Redémarrer VS Code.
  \item Vérifier : dans la vue \textit{Extensions} $\rightarrow$ \textit{Installed}, plus aucun assistant de code ne doit être présent.
\end{enumerate}

\begin{tcolorbox}[attention, title={Complétion et assistant, ce n'est pas la même chose}]
La complétion automatique native de VS Code --- celle qui propose \texttt{addEventListener} quand tu tapes \texttt{addEv} --- reste active et n'est pas concernée. Elle se contente de compléter des noms existants ; elle n'écrit pas de code à ta place.
\end{tcolorbox}

\section{Git et GitHub}
% ============================================================

Les commandes de cette section sont à saisir dans \textbf{Git Bash} (clic droit dans le dossier \texttt{miniforum} $\rightarrow$ \textit{Open Git Bash here}).

\subsection{Configuration de l'identité Git}

À la toute première utilisation de Git sur une machine, il faut indiquer qui tu es : ce nom et cet e-mail seront associés à chacun de tes commits.

\begin{lstlisting}[language=bash, numbers=none]
git config --global user.name "Prenom Nom"
git config --global user.email "ton.email@exemple.com"
\end{lstlisting}

\begin{tcolorbox}[astuce, title={Remarque}]
Cette configuration ne se fait \textbf{qu'une seule fois par machine} : elle vaudra pour tous tes futurs projets Git, pas seulement MiniForum.
\end{tcolorbox}

\subsection{Créer le fichier \texttt{.gitignore}}

\begin{tcolorbox}[attention, title={À faire avant le premier commit}]
Un fichier déjà enregistré dans un commit reste dans l'historique \textbf{même si on l'ajoute au \texttt{.gitignore} par la suite}. Le \texttt{.gitignore} se crée donc \textbf{maintenant}, avant tout \texttt{git add}.
\end{tcolorbox}

Dans VS Code, créer à la racine de \texttt{miniforum} un fichier nommé exactement \texttt{.gitignore} (avec le point initial, et sans extension), puis y copier :

\begin{lstlisting}[caption={\texttt{.gitignore}}]
# Dépendances Node.js : jamais dans Git
node_modules/

# Variables d'environnement (mots de passe, clés d'API)
.env

# Fichiers système
.DS_Store
Thumbs.db

# Réglages locaux de l'éditeur
.vscode/
\end{lstlisting}

\subsection{Premier commit local}

\begin{lstlisting}[language=bash, numbers=none]
cd ~/Documents/Passerelle/Web/miniforum
git init
git branch -M main
git status
git add .
git commit -m "Structure de base du MiniForum"
\end{lstlisting}

\begin{tcolorbox}[astuce, title={Lire la sortie de \texttt{git status}}]
Avant le \texttt{git add}, \texttt{git status} liste les fichiers \textit{non suivis}. Tu dois y voir \texttt{index.html}, \texttt{style.css}, \texttt{app.js} et \texttt{.gitignore} --- et rien d'autre. Prends l'habitude de lire cette sortie avant chaque commit : c'est ce qui évite d'envoyer par erreur un fichier qui n'a rien à y faire.
\end{tcolorbox}

\subsection{Créer un compte GitHub}

Si ce n'est pas déjà fait : aller sur \url{https://github.com}, cliquer sur \textit{Sign up} et suivre les étapes (e-mail, mot de passe, nom d'utilisateur).

\subsection{Créer le dépôt distant}

\begin{enumerate}
  \item Se connecter sur \texttt{github.com}, cliquer sur le bouton \textbf{+} en haut à droite, puis \textit{New repository}.
  \item \textit{Repository name} : \texttt{miniforum}.
  \item Laisser la visibilité en \textit{Public}.
  \item \textbf{Ne cocher aucune case} (\textit{Add a README file}, \textit{.gitignore}, \textit{licence}) : le dépôt doit rester \textbf{vide}, puisque le projet existe déjà sur ta machine.
  \item Cliquer sur \textit{Create repository}.
\end{enumerate}

\begin{tcolorbox}[attention, title={Piège fréquent}]
Si tu coches \textit{Add a README file}, GitHub crée un premier commit sur le dépôt distant. Ton envoi (\texttt{git push}) sera alors refusé, car le dépôt local et le dépôt distant auront des historiques différents. Le plus simple : supprimer le dépôt et recommencer avec un dépôt vraiment vide.
\end{tcolorbox}

\subsection{Envoyer le projet sur GitHub}

Sur la page du dépôt fraîchement créé, cliquer sur le bouton vert \textbf{Code}, onglet \textbf{HTTPS}, et copier l'URL affichée. Puis, dans Git Bash, à la racine de \texttt{miniforum} :

\begin{lstlisting}[language=bash, numbers=none]
git remote add origin https://github.com/ton-login/miniforum.git
git push -u origin main
\end{lstlisting}

\begin{tcolorbox}[astuce, title={Authentification}]
Lors du tout premier \texttt{git push}, une fenêtre s'ouvre dans le navigateur et demande de se connecter à GitHub. C'est normal : GitHub n'accepte plus les mots de passe directement dans le terminal. Il suffit de se connecter une fois --- Git mémorise ensuite la connexion.
\end{tcolorbox}

\subsection{Vérification}

Rafraîchir la page du dépôt sur \texttt{github.com}. Les quatre fichiers doivent y apparaître : \texttt{index.html}, \texttt{style.css}, \texttt{app.js} et \texttt{.gitignore}.

Le dépôt \texttt{miniforum} va évoluer chaque semaine, et son \textbf{historique fait partie de l'évaluation du projet final}. Prends dès maintenant l'habitude de committer à chaque étape logique de ton travail, avec un message clair --- et non en une seule fois à la fin.
\end{tcolorbox}
